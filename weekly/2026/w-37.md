# Weekly Log 37: Exact Boundaries

> 15 September 2026 – 21 September 2026

## Overview

This week moved the recurrence work from implementation into close review. The
six-commit stack had to show more than working behavior: its persisted formats,
restart path, concurrent updates, and tests needed to agree about which layer
owned each fact. Small details carried that weight. Optional `initial_start`,
BigSize values, enum discriminants, malformed records, and payee-key recovery
all exposed places where a plausible test could still leave the actual contract
unproved.

The review also tightened the history. Fixes were moved beside the commits
that introduced the relevant behavior, and the stack was restored after
autosquash. With the recurrence suites passing, the remaining default-suite
failure was isolated to an unrelated VSS nonce test. A separate Onion Message
discussion stayed earlier in its lifecycle, using payload buckets and maximum
path length as concrete starting points for its privacy and reachability
tradeoffs.

## Highlights

### Making persistence say exactly what it means

- Corrected optional `initial_start` persistence, BigSize boundaries, enum
  discriminants, and malformed-record handling.

- Replaced false restart coverage with a manager rebuilt from durable records,
  then verified recovery rather than continued in-memory state.

- Added an atomic transition check so stale writers cannot overwrite newer
  cancellation, retry, or payment state.

- Repaired payee-key recovery coverage and placed serialization fixes in the
  commits whose formats required them.

### Keeping the reviewable stack intact

- Reviewed recurrence as a six-commit progression from dependency adoption
  through durable state, serialization, storage, and manager tests.

- Split unrelated findings from the intended recurrence changes and restored
  the commit sequence with interactive autosquash.

- Ran feature-enabled and default library suites, recurrence tests, formatting,
  and diff validation. The recurrence path passed; the default suite's one
  failure was unrelated to this work.

### Giving an early protocol proposal useful numbers

- Analysed payload-bucket sizes for Onion Message padding and the information
  that message size can expose.

- Analysed maximum Lightning path lengths, balancing network reachability
  against routes that can loop between nodes.

- Recorded preliminary values as inputs for the next protocol discussion,
  without treating either bound as final.

## Reflections

The recurrence review kept returning to one question: what survives after the
process that held the state disappears? A round-trip test can show that current
encoder and decoder agree while both still encode the wrong enum byte. A test
that reuses the same manager can look like restart coverage while never
reconstructing anything. The exact fixtures and rebuilt manager made those
gaps visible.

The storage race made the same point from another direction. Two callers could
validate detached state against the same record, then write their versions in
sequence and lose one transition. The check had to move into the durable
mutation itself. That gives cancellation, retry, and payment updates one place
to reject stale writers, instead of asking every caller to reproduce the same
timing-sensitive rule.

History needed the same discipline. A fix living in the wrong commit makes the
stack harder to review even when the final tree is correct. Moving changes
back to their owning commits made the progression readable again, and the
passing recurrence tests gave that sequence a firm endpoint. The unrelated
default-suite failure was easier to leave alone once its boundary was known.

The Onion Message work had a different pace. Payload buckets and path limits
are still exploratory, but they turn broad privacy and routing questions into
parameters that can be tested. Bigger buckets hide more size variation at a
space cost; longer paths reach farther while making loops harder to reason
about. Next week can challenge those starting points with concrete cases rather
than intuition alone.
