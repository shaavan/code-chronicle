  next invoice request.

## Reflection

The recurrence branch moved into the part that is easy to underestimate from
the field list alone. Offers and invoice requests already had most of their
surface cleaned up, so the next visible task was adding the invoice-side
fields. That sounds smaller than it felt. The invoice is where the next piece
of state comes from, and without that part the branch still reads like two
message extensions sitting near each other.

Adding the `Bolt12Invoice` fields made the flow easier to hold. The offer says
whether recurrence is allowed or required. The invoice request carries the
counter and the previous state. The returned invoice hands back the next state
that the following request has to echo. Once all three pieces were present,
the real pressure moved into parsing: the code had to validate a sequence, not
just a list of fields.

That is where the day slowed down. Some invariants belong directly to the
message carrying the TLV, and those can stay local. Other checks only become
meaningful once the parser knows how the offer, request, and invoice relate to
each other. Pushing too much into one message would make the code guess at
context it does not have yet. Leaving everything local would let invalid
recurrence shapes pass because no single message looked wrong enough on its
own.

The useful part was getting the cross-message structure into place before
trying to finish all the coverage. It gave the invoice fields their real job
in the branch. They are not just another set of parsed values; they carry the
state that lets the next request prove continuity. That changes how the
parser has to think about them, and it makes the remaining tests more
important because most of the interesting failures live at those boundaries.

By the end, the branch had the main recurrence loop wired through the three
messages. It still needs the tests that make the edge cases hard to break,
but the shape is now there: offer terms, request position, returned state, and
the next request tied back to that state. The work felt less like filling in a
draft table and more like teaching the parser the actual rhythm of the
protocol.
