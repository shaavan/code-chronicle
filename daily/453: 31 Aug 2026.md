# Log 453: Seen from Node

> 31 August 2026

## What I worked on

- Finished the [rust-lightning side of recurrence] and moved up the stack to
  prepare the corresponding LDK Node implementation plan.
- Traced the planned Node flow against rust-lightning's public API and found
  upstream pieces that are still unavailable to external callers.
- Identified missing public calendar arithmetic that Node will need to advance
  and validate recurring payment periods.
- Finished the plans for both sides and ordered the next work around filling
  the upstream gaps before beginning the Node implementation.

## Reflection

With the rust-lightning recurrence work finished, I moved up the stack
expecting the LDK Node plan to mostly connect pieces that were already in
place. Writing that plan at the level of actual Node calls challenged the
assumption. The higher-level flow could only use what rust-lightning exposes,
and several pieces needed by the integration were still internal.

Calendar arithmetic was the clearest example. Node needs to advance recurring
periods and validate where a payment sits in the schedule. The underlying
recurrence model already depends on those calculations, while Node cannot
build its side of the flow until the required operations cross
rust-lightning's public boundary. That requirement was easy to miss inside
the upstream implementation and obvious from the first external caller.

That discovery pulled the next work back into rust-lightning for a short pass.
Starting in Node now would mean designing around APIs that still need to move,
then returning to repair the integration once the public surface catches up.
Exposing those operations first gives the Node implementation the boundary it
will actually use.

By the end, both implementation plans were finished and the dependency between
them was explicit. The rust-lightning feature works from inside its own layer;
the next pass makes the missing parts usable from Node. Once that is done, the
Node implementation can begin without carrying temporary workarounds.
