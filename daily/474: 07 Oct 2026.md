# Log 474: One Extra Field

> 07 October 2026

## What I worked on

- Removed pasted diff markers from the regression test in the [dummy-hop rejection fix][dummy-hop-fix] and traced why forwarding hops rejected message-content fields while dummy hops accepted them.
- Confirmed that an unknown odd outer TLV such as type 65 still sets `message_type`, even though the parser skips the field itself.
- Checked how a sender could add that field around unchanged, authenticated blinded routing instructions without knowing the receiver’s secret key. Refined the privacy explanation around probing a selected non-final layer and needing an observable reply.
- Reviewed the dummy-branch rejection check and regression test, then moved the test and its supporting imports into a test-only module to fix their availability in normal library builds. Documented the test’s purpose and flagged missing required AI attribution in the commit message.
- Passed formatting, whitespace checks, and the Rust 1.75 default-library build check. Follow-up corrections remain uncommitted; tests stayed unrun under the repository instructions.

## Reflection

The unknown field was enough to make the two branches behave differently. The parser skipped type 65, but still remembered that a message-content field had appeared. Forwarding used that information to reject the request; dummy processing let it through. Following that small detail made the regression test easier to understand.

I then needed to check what the sender could actually change. The encrypted routing instructions stay intact, while the sender builds the onion layers around them. That leaves room for the extra field without the receiver’s secret key. A probe can target one non-final layer, and repeated replies can expose where dummy layers begin and where the receiver sits in the blinded sequence. The reply condition matters: a missing response could also come from delivery failure or rate limiting. I kept that limit in the explanation rather than treating silence as evidence.

Reviewing the fix brought the work back to a more ordinary problem. The rejection check looked appropriate, but its regression test pulled test utilities into normal library builds. Moving those imports with the test into a test-only module resolved that build problem, and the Rust 1.75 check passed. The corrections still need to join the existing fix-and-test commit, and the test itself still needs a run.
