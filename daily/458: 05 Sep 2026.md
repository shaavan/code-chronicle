## Reflection

The plan began with what looked like a reason to stop. `pay_for_recurrence`
queues its invoice request before inserting pending-payment state, so a
duplicate payment ID can fail after the request has already been queued. That
ordering initially looked like an upstream prerequisite. Reading the ordinary
`pay_for_offer` paths showed the same behavior, which LDK Node already lives
with. The recurrence work was not introducing a new boundary there.

Once that concern moved out of the way, the unfinished parts of the handoff
were mostly decisions Node has to own. Recurrence methods belong on the
existing BOLT 12 payment handler. The caller chooses the initial period for an
explicit-basetime offer from its payment window, while automatic payment is a
per-recurrence option that begins disabled. A separate pause and resume pair
would duplicate the useful behavior: turning automation off already stops
scheduled attempts without taking away manual payment.

The spending boundary needed more care. Each recurrence keeps the requested
amount as well as a hard maximum, with amountless offers requiring an exact
amount. Quantity and payer note stay fixed for its lifetime. Routing and fee
settings do not have the same status. They are operating policy, so a
recurrence can carry an override that may later be changed or cleared; without
one, future attempts use the Node configuration active at that time.

Persistence tied those decisions together. An operation may return an error
only until Node has durably recorded its intent. Failure after that point
belongs in recurrence state. Recovery and event processing must finish before
the scheduler starts, cache misses fall back to the authoritative store, and
lifecycle events carry transition IDs because delivery is at least once.
Terminal records remain until explicit removal, which is unavailable while an
attempt is pending.

By the final pass, the handoff had become a sequence that could be implemented
without hiding these boundaries inside large commits. Durable state comes
before submission, manual progression before scheduling, recovery before
automation, and native Rust APIs before UniFFI bindings. Focused tests follow
the features they protect, with separate plumbing coverage only where
persistence, replay, serialization, or restart behavior needs room of its own.
No source code moved today, but the first commit now has somewhere precise to
begin.
