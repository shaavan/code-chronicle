  fingerprinting concern around dummy-hop payment constraints.

## Reflection

The dummy-hop branch came back to the same kind of question as the earlier
relay-parameter work, only from a tighter angle. The generated dummy hops had
already stopped carrying obviously fake relay values, but the constraints
still had to survive the same inspection. A path can have believable fees and
CLTV deltas and still stand out if the forwarding constraints around it look
invented.

The review point landed because it was specific. `htlc_minimum_msat = 0` is
easy to accept in code, and `max_cltv_expiry = u32::MAX` is convenient when a
test only needs something that will pass validation. Neither value feels like
ordinary channel policy. If dummy hops are meant to hide inside a blinded
path, the defaults cannot quietly carry their own signature.

The max-expiry side made the fix feel less like choosing a better constant and
more like borrowing the real path's accounting. Blinded paths already start
from a downstream bound using the relative expiry, the far-future floor,
latency grace, and the current best block height, then walk backward through
the path by adding each hop's CLTV delta. Dummy hops need to participate in
that same backward accumulation. Otherwise the code is still saying, in a
small field, which layers were added for padding.

The test I want next is also clearer now. It should build one blinded path
without dummy padding and one with dummy padding, then compare the constraints
each hop sees instead of only checking that the padded path validates. That is
the part I like about this review thread: it keeps moving the tests from "does
this special case work" toward "does this special case disappear into the
ordinary case."

I did not finish the whole change today, but the remaining work is no longer
blurry. The next pass needs to wire dummy constraint derivation into the same
shape as normal blinded-path construction and then pin that behavior with a
comparison test. The privacy claim depends on that sameness. Passing
validation is only the floor.
