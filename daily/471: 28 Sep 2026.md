# Log 471: Following the Payment

> 28 September 2026

## What I worked on

- Added the recurrence ID and error declarations needed at the UniFFI boundary while reviewing the [recurrence implementation][recurrence-branch]; the initiation method still needs a binding-friendly signature before it can be exported.
- Kept recurrence state to active and last-successful payment IDs, avoiding a duplicate copy of `PaymentDetails` already held by `PaymentStore`.
- Added integration coverage for validation failures and persisted failed submissions. A deterministic no-route case replaced a manually built offer that LDK rejected for lacking recipient paths.
- Implemented `PaymentSent` lookup and success persistence: match by active payment ID, clear it after success, and record the last successful ID.
- Ran the targeted integration and serialization roundtrip tests successfully. Formatting ran with nightly-option warnings; `cargo check` still reports unrelated incomplete references elsewhere in the in-progress handler.

## Reflection

The state model got easier to follow once payment details stayed in `PaymentStore`. Recurrence only needs to remember which payment is active and which one last succeeded. That also made the failure rule concrete: clear the active ID after a failed attempt, while keeping the last success intact.

Testing the initiation path took a detour. A hand-built offer looked like a route to success coverage, but LDK rejected it because it had no usable recipient paths. Replacing it with a no-route failure kept the test deterministic and still exercised the persisted failed-payment record. The serialization roundtrip passed alongside it.

The `PaymentSent` path now follows the same small state model: find a recurrence by active payment ID, then update it through the store when payment succeeds. The full handler still does not compile because other pieces of the recurrence manager and model are incomplete. That leaves the lookup and persistence behavior in place, while the broader event path still needs its missing types and fields brought together.
