# Log 451: The Missing Ledger

> 26 August 2026

## What I worked on

- Revisited dummy-hop fee reporting after the deferred onion decode path made
  exact recipient-side accounting restart-sensitive.
- Dropped the separate `dummy_skimmed_fees_msat` recipient event field instead
  of adding persistent accumulator state for temporary decode machinery.
- Removed the event-field plumbing, deferred dummy-fee accumulator state, and
  test helper reads that depended on exact dummy-hop fee exposure.
- Rebuilt the remaining stack around dummy-hop behavior: underflow logging,
  fee bucketing, realistic dummy relay constraints, and exposed dummy-hop path
  construction.
- Fixed sender fee expectations so they include sender-paid dummy-hop fees,
  while keeping recipient claimable amount checks tied to the actual amount
  received.
- Cleaned the final comments and reviewed the stack for remaining
  `dummy_skimmed*` symbols or stale exact-fee reporting assumptions.

## Reflection

Today was about deciding which number was worth carrying across a boundary.
The original path could report the exact amount skimmed by dummy hops, but only
while the onion state was still warm. Once decoding moved into the deferred
path, preserving that exact recipient event field meant either storing a new
accumulator or keeping enough original HTLC and onion state around to re-decode
from the top after restart.

That felt like too much structure for the lifetime of this machinery. The
review concern was not only about the field itself; it was about making a
temporary path responsible for restart behavior that persistent
`MonitorEvent`s should eventually handle in a better way. Keeping the exact
field would have made the implementation look more precise while leaving it
attached to state the rest of the design is trying to move past.

So the stack took the smaller shape. Recipient events no longer split out
`dummy_skimmed_fees_msat`. They still expose the normal onion and payment
information needed to understand what was received, and the documentation can
say plainly that some sender-paid fees may belong to blinded path dummy hops.
That keeps the recipient surface honest without making restart persistence pay
for exact accounting that the code cannot naturally preserve yet.

The test repair made the tradeoff visible. Sender fee assertions now include
the full dummy-hop cost, because there is no separate recipient event field to
subtract it back out. But that rule stops at sender fees. Recipient claimable
amount checks still stay on the amount that reaches the recipient, including
the existing blinded-path fee behavior, rather than inheriting every
sender-paid dummy-hop adjustment.

By the end, the branch had a cleaner center. The remaining commits are about
how dummy hops behave, how they are constrained, how fees are bucketed, and how
the path is constructed, rather than about carrying an exact accounting field
through a deferred decode boundary. The one loose end is commit text, not code:
one commit still needs rewording because its body describes stale sampled
relay-parameter history and carries the wrong trailer.
