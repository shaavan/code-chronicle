## Reflection

I went back over the state decision from the previous recurrence session. Allowing
an application to issue an invoice without `next_state`, then hand later requests
to automatic handling, had seemed reasonable when the basetime could still be
recovered. I decided to keep the automatic flow stricter. It always issues state,
so its follow-ups should return that state. An application choosing to omit it
also takes responsibility for the recurrence state and response flow. That gives
the manual path more work, but makes the automatic path easier to reason about.
Missing state still comes from outside the system, so it needs an error rather
than a debug-build assertion.

Splitting the implementation made me look at the history differently. With all
fourteen commits present, the validator was available and the code compiled.
Stopping after the first four exposed a call to a method that would only arrive
with automatic payee handling. I removed that call from the earlier commit while
keeping its amount calculations and timestamp handling. When replaying the later
commit, I kept the validator call that also returns the invoice amount. Both
points in the stack then compiled, and comparing the final code confirmed that
moving the dependency had left the completed implementation intact.

That was useful preparation for asking someone to review a smaller piece. The
message support, automatic responses, and payer APIs each give the reviewer a
different amount of behavior to hold. They still depend on one another, and the
first group needs the small TLV macro change, but each PR can now get tests and
review around its own scope. I kept the consolidated implementation as a draft
and started with the message-support PR.

The descriptions needed the same attention. The tracking issue can explain the
feature, responsibilities, progress, and landing order; the implementation draft
can describe its approach; each smaller PR can carry its detailed checklist. I
prepared that text without changing remote state. Compilation has checked the
rearranged commits, but no tests ran during this work. The next pass still needs
to exercise the behavior those smaller PRs will ask reviewers to trust.
