# Log 468: Less to Carry

> 22 September 2026

## What I worked on

- Continued the [LDK-Node recurrence implementation][recurrence-branch] toward its first usable shape.
- Separated recurrence code that carries necessary storage, lifecycle, and application-facing responsibilities from redundant pieces.
- Reduced overlap between implementation paths so the remaining work has clearer ownership boundaries.
- Prepared a smaller implementation for the next review pass, with less incidental code around the core behavior.

## Reflection

Today’s recurrence work was mostly subtraction. As the implementation started to settle, some pieces were clearly carrying the same responsibility in slightly different forms. Keeping them all would have made the first version look more complete while making its behavior harder to follow.

The useful question became what LDK-Node actually needs to add for recurrence. Rust-Lightning provides protocol support; LDK-Node still needs to hold durable state, manage lifecycle, and expose the behavior through its application-facing surface. Code that did not help those boundaries became easier to question. That left a smaller implementation with fewer places for the same decision to be made twice.

This felt like an important part of reaching a first version. The feature is not finished because the code is smaller, but the remaining path now says more clearly what still needs to be checked. The next review can spend its time on recurrence behavior and its boundaries instead of reconstructing why every surrounding piece exists.
